# Moves and copies are pi's own

**Decision**

`/tree` moves pi's leaf inside the same session file; `/fork` copies the history before a chosen message into a new file; `/clone` is the same copy taken where the chat stands. All three are pi's operations reached as engine commands, and the page follows the new session id the replacement broadcasts. A tree label is pi's `label` entry and the tree filter is pi's `treeFilterMode` setting, so a terminal using the same home shows the same labels and the same filter.

**Why**

main copied sessions through an HTTP route and kept the tree filter in the browser. Neither is needed when the engine owns the session, and a browser-side filter would disagree with pi's own picker.

**Rejected**

A copy route beside the one command boundary; a tree filter stored in Epsilon's own settings.
